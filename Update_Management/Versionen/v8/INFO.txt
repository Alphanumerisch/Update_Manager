📌 API Version v8 – Funktionsübersicht & Änderungen
Diese Version (v8) der API bringt erhebliche Erweiterungen und Optimierungen mit sich. Hier ist eine detaillierte Zusammenfassung aller Funktionen, inklusive Erklärungen:

✅ Authentifizierung & Sicherheit
🔹 Was wurde implementiert?

Nutzer müssen sich mit E-Mail und Passwort anmelden (login).
Ein Token wird generiert und in der Datenbank gespeichert.
Token-Überprüfung für geschützte API-Aufrufe (get_current_user prüft, ob ein Nutzer eingeloggt ist).
Nutzer können sich abmelden (logout), wodurch ihr Token ungültig wird.
💡 Warum ist das wichtig?
➡️ Ohne Authentifizierung hätten alle Nutzer vollen Zugriff auf die API. Durch Token-Validierung können nur autorisierte Benutzer Änderungen vornehmen.

✅ Login & Logout funktionieren
🔹 Was wurde implementiert?

Nutzer können sich mit ihrer E-Mail & Passwort anmelden (login).
Nach dem Login erhalten sie ein Token, das für weitere API-Anfragen benötigt wird.
Beim Logout (logout) wird das Token ungültig gemacht und in die invalid_tokens-Tabelle eingetragen.
💡 Warum ist das wichtig?
➡️ So wird sichergestellt, dass sich nur berechtigte Benutzer anmelden können. Zudem verhindert es Missbrauch durch abgelaufene oder gestohlene Tokens.

✅ Benutzerinformationen abrufen
🔹 Was wurde implementiert?

Mit get_current_user können angemeldete Nutzer ihre Informationen abrufen.
Wird das Token als ungültig erkannt, erhält der Nutzer einen Fehler (401 Unauthorized).
💡 Warum ist das wichtig?
➡️ Erlaubt es dem Nutzer, seine Anmeldedaten zu überprüfen und sicherzustellen, dass er eingeloggt ist.

✅ Kundenverwaltung (Hinzufügen, Abrufen, Löschen)
🔹 Was wurde implementiert?

Kunden können hinzugefügt werden (add_customer).
Eine Liste aller Kunden kann abgerufen werden (list_customers).
Kunden können gelöscht werden (delete_customer).
💡 Warum ist das wichtig?
➡️ Ein zentraler Bestandteil der API, da Nutzer so Kunden verwalten und gezielt Daten organisieren können.

✅ Updates & Dashboard abrufen
🔹 Was wurde implementiert?

Nutzer können eine Liste aller Updates abrufen (list_updates).
Das dashboard gibt eine Übersicht über Kunden & ihre Updates zurück.
💡 Warum ist das wichtig?
➡️ Unternehmen oder Nutzer können ihre Änderungen verwalten und nachvollziehen, welche Updates an Kunden gesendet wurden.

✅ Updates an Kunden senden
🔹 Was wurde implementiert?

Mit send_update kann ein Update an Kunden versendet werden.
Jeder Kunde bekommt einen individuellen Link mit einem Token.
Die API stellt sicher, dass Kunden nicht mehrfach das gleiche Update erhalten.
💡 Warum ist das wichtig?
➡️ So kann sichergestellt werden, dass Kunden personalisierte Updates erhalten und der Status der Kommunikation nachverfolgt werden kann.

✅ Kunden und Updates löschen
🔹 Was wurde implementiert?

delete_customer entfernt einen Kunden aus der Datenbank.
delete_update löscht ein Update, inklusive der Kunden-Verknüpfungen.
💡 Warum ist das wichtig?
➡️ Verhindert eine Überfüllung der Datenbank und ermöglicht es, alte oder falsche Einträge zu entfernen.

✅ Neue Action: add_customer_to_update
🔹 Was wurde implementiert?

Nutzer können nachträglich Kunden einem Update zuweisen.
Wenn customer_updates bereits einen Eintrag für einen Kunden hat, wird kein doppelter Eintrag erzeugt.
💡 Warum ist das wichtig?
➡️ Vorher konnte ein Update nur einmalig versendet werden. Jetzt ist es möglich, nachträglich neue Kunden hinzuzufügen.

✅ Erweiterung der Action list_updates
🔹 Was wurde geändert?

list_updates gibt nun auch eine Liste der zugeordneten Kunden zu jedem Update aus.
💡 Warum ist das wichtig?
➡️ Vorher wurden nur Updates angezeigt. Jetzt können Nutzer direkt sehen, welche Kunden ein bestimmtes Update erhalten haben.

📌 Fazit & Bedeutung der v8-Version
Die Version 8 bringt: ✔ Komplette Authentifizierung & Sicherheit
✔ Vollständige Kundenverwaltung
✔ Umfassende Update-Funktionalität
✔ Erweiterungen für bessere Nachverfolgbarkeit & Usability
